# Technical Writing Best Practices

Structure: pyramid principle (conclusion first, then supporting points). Use active voice, short sentences (<25 words). Headings: descriptive, hierarchical (H1->H2->H3). Diagrams over text for complex flows (Mermaid, Excalidraw). Code examples: consistent style, show compilable/runable snippets, include expected output. API docs: endpoint, method, auth, request/response schemas (examples), error codes. README: what+why first, then quickstart, then details. Keep docs versioned alongside code (docs-as-code). Spell check, lint (vale, write-good).
