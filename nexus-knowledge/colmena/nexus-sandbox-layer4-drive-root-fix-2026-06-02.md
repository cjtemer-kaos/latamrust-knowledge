# nexus-sandbox-layer4-drive-root-fix-2026-06-02

Sandbox fix Layer 4 agregado: Windows drive root no-escribible. Cuando LLM dice 'crea X en d:' o usa path 'D:\\file.txt' directo (raíz), sistema auto-fallback a 'D:\\Temp\\file.txt' con warning. Root cause: '[Errno 22] Invalid argument' en drive roots requiere admin. Implementado en `src/tools/builtin.py:WorkspaceTools` con `_resolve_drive_root_intent()` helper. Layer 3 (_validate_path) ahora detecta `Path('D:\\').parts == ('D:\\',)` y `Path('D:\\file.txt').parts == ('D:\\', 'file.txt')`. System prompt actualizado en `src/brain/identity.py:get_context_prompt` con regla 7 explicando drive root bloqueado. Test unit pasó: T1 (create_file location D:\\) → D:\\Temp\\prueba_direct_t1.txt, T3 (write_file path D:\\file) → D:\\Temp\\file con warnings. Restart NEXUS server (PID 22932) con fix cargado.
